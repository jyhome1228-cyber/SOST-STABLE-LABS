STUDY 03 · SSL / SECURITY

SSL 인증서는 왜 필요하고
HTTPS는 무엇을 바꾸는가?

주소창의 자물쇠는 단순한 장식이 아닙니다. 브라우저와 서버 사이의 통신을 암호화하고, 사용자가 접속한 서버가 해당 도메인에 대한 인증서를 제시했는지 확인하는 기본 보안 구조입니다.

01 / SSL & TLS

보통 SSL이라고 부르지만 실제 웹에서는 TLS 기반 HTTPS를 사용합니다.

실무에서는 관습적으로 SSL 인증서라고 부르지만 현대 웹의 암호화 통신은 TLS를 사용합니다. 중요한 점은 브라우저가 서버와 통신을 시작할 때 인증서를 확인하고, 이후 주고받는 데이터를 암호화된 연결 위에서 전달한다는 것입니다.

핵심

인증서는 “이 도메인으로 접속한 사용자에게 이 서버가 적절한 인증 정보를 제시한다”는 연결의 출발점입니다.

02 / HTTPS

HTTPS는 로그인 페이지뿐 아니라 일반 기업 사이트에도 기본값입니다.

HTTP 연결은 중간 구간에서 데이터가 노출되거나 변조될 위험이 있습니다. HTTPS는 브라우저와 서버 사이의 통신을 암호화해 이런 위험을 낮춥니다.

  • 폼 입력과 로그인 정보 보호
  • 전송 중 콘텐츠 변조 위험 감소
  • 브라우저의 안전하지 않음 경고 방지
  • 외부 API·결제·로그인 연동의 기본 조건 충족
  • HTTP와 HTTPS 주소가 섞여 생기는 중복 URL 문제 예방

03 / CERTIFICATE

인증서는 서버에 한 번 올리고 끝나는 파일이 아니라 유효기간을 관리해야 하는 운영 항목입니다.

인증서는 발급 기관과 서비스 방식에 따라 직접 설치할 수도 있고 호스팅·CDN·웹빌더에서 자동으로 발급될 수도 있습니다. 중요한 것은 도메인이 올바른 서버를 가리키고 인증서가 해당 도메인을 포함하며 갱신이 지속되는지입니다.

실무에서 확인할 것

  • www 포함 여부와 루트 도메인 인증 범위
  • 자동 갱신이 실제로 동작하는지
  • 도메인이나 DNS 이전 시 인증서 재발급 여부
  • HTTP 요청을 HTTPS로 리디렉션하는지

04 / COMMON ERRORS

SSL 오류처럼 보여도 실제 원인은 DNS나 콘텐츠 경로인 경우가 많습니다.

사이트 이전 직후 인증서 오류가 생기면 인증서 자체만 볼 것이 아니라 도메인이 어느 서버를 가리키는지 함께 확인해야 합니다. DNS가 예전 서버를 가리키거나 프록시 설정이 어긋나면 정상 인증서가 있어도 다른 서버의 인증서를 받게 됩니다.

  • 인증서 만료
  • 도메인 이름 불일치
  • DNS가 예전 서버를 가리킴
  • HTTPS 페이지에서 HTTP 이미지·스크립트를 불러오는 Mixed Content
  • 리디렉션 루프 또는 잘못된 프록시 설정

05 / OPERATION

SSL은 사이트 오픈 체크리스트가 아니라 도메인 운영의 일부로 관리합니다.

도메인과 호스팅을 이전하거나 네임서버를 바꾸는 순간 인증서 설정도 함께 영향을 받을 수 있습니다. 따라서 DNS, 배포, 인증서 갱신 상태를 하나의 운영 흐름으로 확인하는 편이 안전합니다.
